# Welcome to Novus

**Novus is a modern systems programming language designed specifically for the Amiga 68k family of computers.**

> *"New code for classic machines"*

## What is Novus?

Novus is a compiled language that brings modern programming language features to the Amiga platform while respecting the constraints and character of 68k systems. It compiles to native Motorola 68000-series machine code, producing standard Amiga HUNK format executables that run on real hardware and emulators.

Unlike cross-platform systems languages, Novus is **Amiga-first** - designed from the ground up to leverage the unique architecture of Amiga hardware and AmigaOS, not to abstract it away.

## Why Novus?

### Modern Ergonomics

- **Clean, readable syntax** inspired by Rust and Zig
- **Strong static typing** with type inference
- **No null pointers** - use `Option[T]` instead
- **No exceptions** - use `Result[T, E]` for error handling
- **Pattern matching** for expressive control flow
- **Inline assembly** when you need direct hardware access

### Amiga-Native Features

- **Direct hardware access** - Copper, Blitter, Paula, custom chips
- **AmigaOS integration** - First-class support for Exec, Intuition, Graphics, DOS
- **Library/Device development** - Build shared libraries and devices
- **Multiple CPU targets** - 68000, 68020, 68030, 68040, 68060
- **Zero runtime overhead** - No garbage collection, no hidden allocations

### Safety Without Sacrifice

- **Explicit memory management** - You control every allocation
- **Bounds checking** in debug builds (removable in release)
- **RAII-style resource handling** with `defer` blocks
- **Type-safe hardware access** - Compiler-validated register operations
- **Unsafe blocks** clearly marked when needed

## Who is Novus For?

Novus is ideal for:

- **Amiga enthusiasts** who want to create new software for classic hardware
- **Demo scene developers** who need precise control over hardware timing
- **RetrocompL developers** exploring 68k programming with modern tools
- **System programmers** who value explicit control and predictable performance
- **Anyone** who loves the Amiga and wants to write code that respects the platform

## Current Status

**Proof of Concept Complete** ✅

The Novus compiler is in active development with a working end-to-end pipeline:

- ✅ Full lexer and parser (ANTLR4-based)
- ✅ IR (Intermediate Representation) generation
- ✅ CPU-target aware code generation (68000-68060)
- ✅ Optimization pipeline (6 passes, 4 optimization levels)
- ✅ VBCC toolchain integration (assembly and linking)
- ✅ Generates valid Amiga HUNK executables
- ✅ 77+ passing unit tests
- ✅ Proper Amiga ABI compliance

**Currently Supported Features:**

- Integer types (u8, u16, u32, u64, i8, i16, i32, i64)
- Functions with parameters and return values
- Arithmetic operations (+, -, *, /, %)
- Control flow (if/else, loops)
- Pattern matching basics
- CPU-specific optimizations

**In Active Development:**

- Structs and enums
- Result/Option types
- Standard library
- AmigaOS API wrappers
- Async/await (stackless coroutines)
- Hardware DSLs (Copper, Blitter, Paula)

## Example Code

Here's a taste of Novus syntax:

```novus
// Simple function demonstrating modern syntax
fn calculate_area(width: u32, height: u32) -> u32 {
    return width * height
}

fn main() -> i32 {
    let area = calculate_area(320, 256)
    return 0
}
```

This compiles to clean, efficient 68k assembly:

```asm
; Generated by Novus compiler
; Target: Motorola 68000

section text,code

xdef _calculate_area
_calculate_area:
    move.l  4(sp),d0      ; width
    move.l  8(sp),d1      ; height
    mulu.w  d1,d0         ; width * height
    rts

xdef _main
_main:
    move.l  #320,-(sp)
    move.l  #256,-(sp)
    bsr.w   _calculate_area
    addq.l  #8,sp
    moveq   #0,d0
    rts
```

## Design Philosophy

Novus follows five core principles:

1. **Explicit over implicit** - No hidden allocations or runtime magic
2. **Predictable performance** - Deterministic execution, no garbage collection
3. **Readable syntax over cleverness** - Code should be obvious
4. **Respect the machine** - Leverage Amiga hardware, don't hide it
5. **Amiga first** - Not a cross-platform language, but an Amiga revival
