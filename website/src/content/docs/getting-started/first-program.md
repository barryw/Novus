# Your First Novus Program

Let's write a simple Novus program, compile it, and run it on an Amiga emulator. By the end of this tutorial, you'll understand the basic compilation workflow and be ready to explore more advanced features.

## Hello, Amiga!

Create a new file called `hello.novus` with the following content:

```novus
// Your first Novus program!
fn main() -> i32 {
    return 42
}
```

This is a minimal Novus program. Let's break it down:

- `//` - Single-line comment
- `fn main()` - Declares the main function (entry point)
- `-> i32` - Function returns a 32-bit signed integer
- `return 42` - Returns the value 42 to the operating system
- `{` `}` - Curly braces define the function body

When this program runs on AmigaOS, it will exit with status code 42. You can check this in the Shell with the `echo $rc` command.

## Compiling Your Program

Now let's compile the program to an Amiga executable:

```bash
# Navigate to your Novus installation directory
cd ~/novus  # Or wherever you cloned Novus

# Compile hello.novus
dotnet run --project Novus/Novus.csproj -- hello.novus -o hello

# This produces an Amiga executable named "hello"
```

If compilation succeeds, you'll see output similar to:

```
Novus Compiler v0.1.0
Compiling hello.novus...
Generating 68020 assembly...
Assembling with vasm...
Linking with vlink...
Success: hello
```

## Understanding the Compile Command

Let's look at the compile command in detail:

```bash
dotnet run --project Novus/Novus.csproj -- hello.novus -o hello
│                                         │             │
│                                         │             └─ Output file name
│                                         └─────────────── Input source file
└───────────────────────────────────────────────────────── Runs the Novus compiler
```

### Common Compiler Options

| Option | Description | Example |
|--------|-------------|---------|
| `-o <file>` | Output file name | `-o myprogram` |
| `--cpu <target>` | Target CPU (68020, 68030, 68040, 68060) | `--cpu 68020` |
| `--emit-asm` | Output assembly only (don't assemble/link) | `--emit-asm` |
| `--emit-ir` | Output intermediate representation | `--emit-ir` |
| `-O <level>` | Optimization level (0-3) | `-O 2` |
| `-v, --verbose` | Verbose compilation output | `-v` |
| `--vbcc-path <path>` | Path to VBCC installation | `--vbcc-path /opt/vbcc` |
| `--ndk-path <path>` | Path to Amiga NDK | `--ndk-path /opt/amiga/ndk39` |

### Examples

**Compile for 68020 with optimizations:**
```bash
dotnet run --project Novus/Novus.csproj -- hello.novus -o hello --cpu 68020 -O 2
```

**Generate assembly output only:**
```bash
dotnet run --project Novus/Novus.csproj -- hello.novus --emit-asm -o hello.s
```

**Verbose compilation:**
```bash
dotnet run --project Novus/Novus.csproj -- hello.novus -o hello -v
```

## Viewing the Generated Assembly

To see what assembly code the compiler generated, use the `--emit-asm` flag:

```bash
dotnet run --project Novus/Novus.csproj -- hello.novus --emit-asm -o hello.s
cat hello.s
```

You'll see clean, readable 68k assembly:

```asm
; Generated by Novus compiler
; Target: Motorola 68020
; Source: hello.novus

	section	text,code

	xdef	_main

_main:
	moveq	#42,d0      ; Load 42 into d0 (return value register)
	rts                 ; Return to caller
```

Notice how the compiler:
- Uses the efficient `moveq` instruction for small constants
- Returns the value in register `d0` (Amiga ABI convention)
- Generates clean, minimal assembly

## Running Your Program

### On an Emulator

1. **Copy the executable to your emulator's shared directory:**

   ```bash
   # Example: WinUAE shared folder
   cp hello /path/to/winuae/shared/hello
   ```

2. **Start your Amiga emulator** (WinUAE, FS-UAE, etc.)

3. **In the Amiga Shell, navigate to the shared directory:**

   ```
   CD Work:
   hello
   echo $rc
   ```

   You should see `42` printed - the return value from your program!

### On Real Hardware

Transfer the `hello` executable to your Amiga using:
- CF/SD card adapter
- Serial transfer
- Network transfer (if you have a network card)
- Floppy disk

Then run it from the Shell:
```
hello
echo $rc
```

## A More Interesting Example

Let's create a program that does some computation:

**arithmetic.novus:**
```novus
// Calculate the area of a rectangle
fn calculate_area(width: u32, height: u32) -> u32 {
    return width * height
}

fn main() -> i32 {
    let area = calculate_area(320, 256)
    // For a 320x256 screen, area = 81920 pixels
    return area as i32
}
```

Compile it:
```bash
dotnet run --project Novus/Novus.csproj -- arithmetic.novus -o arithmetic --cpu 68020
```

This demonstrates:
- Function definitions with parameters
- Type annotations (`u32` = unsigned 32-bit integer)
- Local variables with `let`
- Function calls
- Type casting with `as`

## Understanding CPU Targets

Novus supports multiple 68k CPU targets. Choose the one that matches your target hardware:

| Target | Best For | Features |
|--------|----------|----------|
| `68020` | **Default recommended** (A1200, accelerated A500/A2000) | 32-bit operations, more addressing modes, good balance |
| `68030` | A3000, A4000 (most common) | Same as 68020 with MMU |
| `68040` | High-end A4000 | Optimized for pipeline, avoid slow instructions |
| `68060` | Accelerator cards | Maximum performance, strict instruction selection |

**Example: Compile for 68020 (default, wide compatibility):**
```bash
dotnet run --project Novus/Novus.csproj -- hello.novus -o hello --cpu 68020
```

**Example: Compile for 68040 (fast A4000):**
```bash
dotnet run --project Novus/Novus.csproj -- hello.novus -o hello --cpu 68040 -O 3
```

## Optimization Levels

Novus supports four optimization levels:

| Level | Description | Use Case |
|-------|-------------|----------|
| `-O 0` | No optimization, fast compilation | Debugging |
| `-O 1` | Basic optimizations (constant folding, DCE) | Development |
| `-O 2` | **Default** - Standard optimizations | General use |
| `-O 3` | Aggressive optimizations | Release builds |

**Example:**
```bash
# Debug build (no optimization)
dotnet run --project Novus/Novus.csproj -- hello.novus -o hello -O 0

# Release build (maximum optimization)
dotnet run --project Novus/Novus.csproj -- hello.novus -o hello -O 3
```

## Project Workflow

As your programs grow, you'll want to organize them into projects. Here's a recommended structure:

```
myproject/
├── novus.toml          # Project configuration
├── src/
│   └── main.novus      # Main source file
├── build/              # Compiled outputs (gitignored)
└── README.md
```

**novus.toml** (project configuration):
```toml
[package]
name = "myproject"
version = "0.1.0"

[build]
target_cpu = "68020"
optimization = 2
output_dir = "build"
```

This structure allows you to build with a simple command:
```bash
novus build  # Reads novus.toml and compiles accordingly
```

## Troubleshooting

### Compilation Errors

**Syntax error:**
```
Error: Unexpected token 'let' at line 5:10
```
Check your syntax - Novus has strict parsing rules.

**Type error:**
```
Error: Cannot assign i32 to u32 without explicit cast
```
Use explicit type casting: `value as u32`

**VBCC errors:**
```
Error: vasmm68k_mot not found
```
Ensure VBCC is installed and in your PATH (see [Installation Guide](/getting-started/installation/)).

### Runtime Issues

**Program crashes on Amiga:**
- Check you compiled for the correct CPU target
- Use `-O 0` to disable optimizations and test
- Verify your Amiga has enough memory

**Wrong return value:**
- AmigaOS uses `d0` register for return values
- Values are treated as signed 32-bit integers
- Maximum return value is 2147483647
